### 3.4 교육 탭 스크롤 (`education.js`, `theme.css`)
- 교육 탭은 가이드 원본(`education/index.html`)을 iframe으로 넣는다. 고정 높이 때문에 안쪽 스크롤과 바깥 스크롤이 겹쳐 보였다.
- 지금은 `autoSize`가 iframe 높이를 가이드 내용 길이에 맞춰 **바깥 페이지 스크롤 하나만** 쓴다.
  - 원본의 `scrollTo`·`scrollY`·`pageYOffset`을 바깥 페이지 기준으로 바꿔 "맨 위로 이동" 등이 그대로 작동한다. 바깥 페이지가 `scroll-behavior: smooth`라서 즉시 이동은 `behavior:"instant"`로 호출한다.
  - 원본의 `<dialog>`(이미지 확대·편집)는 iframe 화면 가운데에 뜨므로, 열려 있는 동안만 iframe을 화면 높이로 줄이고 그 위치로 올라간다. 닫으면 높이와 스크롤 위치를 되돌린다.
  - 원본의 `.layout{min-height:100vh}`는 iframe 높이가 내용에 맞춰질 때 계속 커지게 만들어서, 주입하는 스타일에서 `min-height:0`으로 덮어쓴다. 원본에 `100vh`를 쓰는 CSS가 늘면 같은 문제가 생긴다.

### 3.6 화면 오류 두 가지 수정 (`education.js`, `records.js`)
오류확인 화면의 "최근 오류"에서 찾았다.
- **`ResizeObserver loop completed with undelivered notifications`**: 3.4에서 넣은 교육 탭 코드가 만든 오류였다(앱에서 `ResizeObserver`를 쓰는 곳은 이 한 곳). 교육 탭을 떠날 때마다 기록됐다.
  이제 크기 변화를 다음 프레임에 처리하고 가이드가 닫히면 관찰을 끝낸다. 로컬에서 열기·닫기 4번 반복 시 오류 0건.
- **기록 탭 `TypeError: Cannot set properties of null (setting 'textContent')`**: 기록 탭이 서버 응답을 기다리는 사이 다른 화면으로 가면 칸이 사라져서 생겼다(오류를 받는 `catch`도 같은 칸에 써서 처리되지 않은 오류가 됨).
  `records.js`의 칸 찾기가 칸이 없으면 화면에 없는 임시 칸을 돌려주게 했다. 로컬에서 재현 후 수정 확인.
- 배포 화면에서 새 오류가 더 쌓이지 않는지는 아직 보지 못했다. 이미 기록된 오류는 그대로 남는다.

7. 일부 가입자의 오래된 수집 실패(예: 한 계정의 실패 9건)는 최근 100건 표 밖이라 원인을 확인하지 못했다.

## 6. 이번에 배운 것 (같은 실수 방지)
- 푸시가 거절되면(원격에 새 커밋) 내용과 겹치는 파일을 먼저 본다. 한 줄로 길게 쓴 코드(`customers.js`)는 줄 단위로 합쳐지지 않으므로,
  원격 최신 파일을 기준으로 두고 내 수정을 문자열 치환으로 다시 적용한 뒤 `node --check`와 화면 확인을 한다.
- 같은 NRC 계정이 두 사이트 계정에 등록돼 있으면 한꺼번에 돌릴 때 같은 계정이 동시에 두 번 로그인한다. 대량 실행 전에 `nrc_cloud_credentials`에서 겹침을 먼저 본다.
- `delete`/`update`는 `returning`을 붙이지 않으면 SQL Editor에 "No rows returned"만 나와 몇 건이 바뀌었는지 알 수 없다. 바꾼 뒤 `select count(*)`로 확인한다.
- 로그인이 필요한 화면은 `supabase.js`를 가짜 모듈로 바꾼 임시 페이지(import map)에서 모듈을 불러 확인할 수 있다. 임시 파일은 확인 후 지운다.
- 화면 확인 때는 CSS를 `app.css`와 `theme.css` 둘 다 불러야 실제와 같은 모양이 나온다.
- `?v=`는 수정한 모듈을 가져오는 모든 곳을 같이 올린다(예: `box-tree.js`는 4곳, `custom-tree.js`는 `app.js`와 `manual-close.js`).

## 7. 지켜야 할 것 (CLAUDE.md 요약)
- 운영 DB 전체 SQL 재실행·초기화 금지. 새 표는 `authenticated`와 `service_role` 둘 다 GRANT.
- 프런트엔드 변경 시 import `?v=`와 `index.html` 앱 버전을 함께 올린다.
- 계정 비밀번호·토큰·키를 소스·문서·로그에 넣지 않는다. 사용자가 요청하기 전에는 실제 등록 PC를 해제하지 않는다.

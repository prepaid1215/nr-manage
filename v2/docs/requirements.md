# 기획안 1.0 구현 기준

업무 흐름은 `파트너 → 활동 → 고객 → 개통 → 실적 → 조직 → 수당 → 마감`으로 연결한다.

1차 메뉴는 홈, 고객, 활동, 조직, 실적, 수당, 마감, 설정이다. 모바일 하단에는 홈, 고객, 활동, 조직, 더보기를 둔다.

일반 파트너는 자기 정보와 고객, 실적, 체크리스트, 활동, 수당, 마감매출을 본다. 상위 파트너는 산하 파트너·고객·활동·실적·매출·현황을 추가로 본다. 수정과 삭제는 서버에서 소유권을 확인한다.

## 데이터 공개 원칙

- 기본 상태에서는 모든 파트너 계정을 서로 완전히 분리한다.
- 하위 사업자는 상위 사업자의 고객, 활동, 매출, 수당, 마감 및 개인 정보를 볼 수 없다.
- 서로 다른 파트너 사장님의 데이터는 계보상 관계가 있더라도 자동으로 공개하지 않는다.
- 조직 계보는 실적 계산용 관계와 운영 데이터 공유 권한을 분리한다.
- 팀 가입만으로 모든 데이터가 공개되지 않는다. 팀별 역할과 공유 범위를 별도로 검사한다.
- 자기 데이터는 본인만 생성·조회·수정·삭제할 수 있다.
- 팀장은 팀원이 공유를 허용한 업무 데이터 또는 팀 정책으로 지정된 항목만 조회할 수 있다.
- 팀원은 다른 팀원의 데이터나 팀장의 개인 데이터를 기본적으로 조회할 수 없다.
- 관리자는 운영과 계정 정지를 수행할 수 있지만, 민감 데이터 열람은 별도 감사 대상이다.

## 팀 권한 모델

- `OWNER`: 팀 설정과 팀원 관리, 허용된 팀 공유 데이터 조회
- `MANAGER`: 허용된 팀 업무 데이터 조회·관리
- `MEMBER`: 자기 데이터 관리, 명시적으로 공유된 팀 자료 조회
- `VIEWER`: 공유된 요약 데이터만 읽기

공유 범위는 `customers`, `activity`, `checklist`, `sales_summary`, `organization_summary` 단위로 설정한다. `commission`, `password`, `private_memo`는 팀 공유 대상에서 제외한다.

Supabase에서는 모든 업무 테이블에 `owner_id`와 선택적 `team_id`를 저장하고 RLS에서 `auth.uid() = owner_id` 또는 유효한 팀 권한이 있을 때만 접근시킨다. 프론트엔드의 버튼 숨김은 보조 UI일 뿐이며 실제 차단은 데이터베이스 정책에서 수행한다.

저장 시트는 Users, Sessions, Relations, Customers, Daily, Checklist, Commission, ClosingSales, Plans, Settings, Logs다. NRC 계보·NV와 월별 마감 JSON은 외부 동기화 데이터로 별도 연결한다.

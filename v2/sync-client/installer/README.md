# NRC Sync 설치파일

`NRCSync.exe` 파일 하나만 있으면 됩니다.

현재 버전은 `20261108-auto-update-1`입니다. 회선 누락 수정과 자동 업데이트 기능을 포함합니다.
자동 업데이트가 없던 기존 PC는 이번 버전을 한 번 직접 받아 설치해야 합니다.
이후에는 실행 후와 30분마다 새 버전을 확인해 자동으로 교체합니다. 기존 PC 등록 정보와 저장한 계정은 유지됩니다.

2026-11-08 이전 배포 파일은 Defender가 `Trojan:Win32/Sabsik.FL.A!ml`로 탐지하여 배포를 중단했습니다.
격리된 파일을 복원하거나 백신 예외를 추가하지 마세요. 현재 배포 파일의 버전·해시는 `version.json`,
검사 기록은 `security-check.json`에서 확인할 수 있습니다. 검사 기록은 해당 시점 Defender 검사 결과입니다.

## 설치 방법

1. `NRCSync.exe`를 그 PC의 아무 위치(다운로드 폴더, 바탕화면 등)에 복사합니다.
2. 더블클릭으로 실행합니다. (아직 설치되지 않으며, 그냥 그 자리에서 켜집니다)
   - NRC 수집용 브라우저를 자동으로 설치합니다(1~2분 소요, 최초 1회만).
3. 앱(웹)에 로그인한 상태로 설정 > 수집 PC 탭에서 **"이 PC 자동 등록"**을 누릅니다
   (미리 '공유 PC 수집 승인'을 해둔 계정이어야 합니다). 이 버튼을 누르는 순간
   비로소 이 PC에 `%LOCALAPPDATA%\NRCSync`로 자동 설치되고, Windows 로그인 시
   자동 실행되도록 등록됩니다 — 입력창 없이 한 번에 끝납니다.
   - 자동 등록이 안 되면 옆의 "수동 등록"으로 예전처럼 직접 입력할 수 있습니다.
4. 처음 복사했던 `NRCSync.exe`(다운로드 폴더 등)는 이제 지워도 됩니다 — 이미
   `%LOCALAPPDATA%\NRCSync`에 복사되어 그쪽이 실제로 사용됩니다.

## 이후 동작

- Windows에 로그인할 때마다 자동으로 조용히(창 없이) 백그라운드에서 실행됩니다.
- 실행 중에는 작업표시줄 오른쪽 아래 트레이 아이콘에 NRC Sync 아이콘이 뜹니다.
  - 클릭(또는 더블클릭): 앱 웹페이지가 열립니다.
  - 마우스 오른쪽 클릭 → 종료: 이 PC의 수집 기능을 끕니다.
- 이 PC를 켜두는 동안은 "온라인" 상태로 잡혀서 공유 수집 요청을 처리할 수 있습니다.
- 별도로 실행할 필요가 없습니다. 껐다 켜도 다시 자동으로 시작됩니다.
- 새 버전은 고정된 공식 배포 주소에서만 받으며 크기·SHA-256·Windows 실행 파일 헤더를 확인합니다.
- 진행 중인 수집·업로드·메모장 작업을 기다린 뒤 교체합니다. 10분 안에 끝나지 않으면 다음 확인 때 다시 시도합니다.
- 새 버전의 정상 시작을 확인하지 못하면 이전 실행 파일로 복구하고, 같은 버전 재시도는 하루 미룹니다.
- 트레이 아이콘 오른쪽 클릭 → **업데이트 확인**에서 즉시 확인하거나 상태를 볼 수 있습니다.
- 개발용 `python api.py` 실행은 자동으로 EXE를 설치하거나 교체하지 않습니다.

## 확인/제거

- 실행 중인지 확인: 트레이 아이콘 확인, 또는 작업 관리자에서 `NRCSync.exe` 프로세스 확인
- 오류가 있었다면 로그 파일: `%LOCALAPPDATA%\NRCSync\nrcsync.log`
- 완전히 제거:
  1. 트레이 아이콘 오른쪽 클릭 → 종료 (또는 작업 관리자에서 `NRCSync.exe` 프로세스 종료)
  2. `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\NRCSync.vbs` 삭제 (자동 실행 해제)
  3. `%LOCALAPPDATA%\NRCSync` 폴더 삭제
  4. 웹 앱 설정 > 수집 PC 목록에서도 해당 PC 항목을 지워주세요(관리자만 가능)

## 배포용 빌드

1. 별도 가상 환경에 `requirements-build.txt`의 고정 버전을 공식 PyPI에서 설치합니다.
2. `sync_version.py`의 `APP_RELEASE`를 이전 배포보다 큰 정수로 변경하고 수집기 버전도 변경합니다.
3. 그 환경의 Python으로 `build_release.py`를 실행합니다. 후보 파일만 `build/candidate`에 만들며 자동 게시하지 않습니다.
4. 후보 EXE를 Defender 사용자 지정 검사로 검사하고 완료 이벤트와 탐지 기록을 확인합니다. 차단되면 배포하지 않습니다.
5. 검사한 동일한 EXE와 `version.json`을 이 폴더에 복사하고 검사 시점·엔진·SHA-256을 `security-check.json`에 기록합니다.
6. EXE와 manifest를 같은 커밋으로 게시합니다. 게시 후 해시를 다시 확인합니다. 웹 앱의 `SYNC_DOWNLOAD`는 이 게시 커밋의 고정 URL로 변경하여 이전 다운로드 캐시를 방지합니다. 배포 중단 시 manifest에 `disabled: true`를 설정하고 웹 앱의 다운로드 링크도 중단합니다.

다운로드 검증은 파일 변조·손상을 확인합니다. 악성코드 검사나 실행 파일 서명을 대신하지 않습니다.
